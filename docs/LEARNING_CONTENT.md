# Educational Content Handbook — Sunday Marketing Study Book

## Mission and source hierarchy

Learner-facing content must faithfully reconstruct the **lecture actually delivered** in this Sunday cohort. Academic reference provides concept accuracy; classroom transcript, delivered teaching material and recorded discussion provide the specific lesson chronology. **Never mix sources into a fictional event.**

Source preference:
1. Instructor-approved lesson scope/material and actual classroom delivery.
2. Verified audio transcript + classroom examples/discussions (correct transcription errors only when independently verified).
3. Authoritative academic reference (e.g., established Marketing textbooks and reputable educational sources).
4. Instructor's authorized explanation / editorial bridge; mark as editorial explanation, not as a verbatim classroom quote.
5. Private performance/assessment information may guide follow-up, **never publish individually identifying results**.

Keep citations/traceability in private source-workflow; public build should not leak private raw inputs.

## Learning architecture

The settled student learning journey comprises **Explore → Understand → Challenge Yourself → Apply & Review**, expressed as reading and interactions:
- **Concept Scene** in logical sequence; relates to previous/next material; academically accurate definition/concept.
- **Instructor explanation** in readable *professional Egyptian colloquial Arabic*; natural, direct, human; essential Marketing terms remain English.
- **Evidence-backed classroom example or discussion**, only where actually said and publishing is permitted. Distinguish hypothetical examples.
- **Learning Objective** and contextual glossary, not jargon dumping.
- **Mini-Case** at the start of each unit: one distinct case per unit, not one case repeated for an entire lecture.
- **Quick Check** on a pivotal idea with feedback; should not simply leak every final-quiz question.
- **Decision Lab** tests a relevant commercial decision.
- **KEY TAKEAWAYS** = concise educational summary at the end of each unit, not a written-response exercise; avoid visual redundancy.
- **End-of-lecture practice quiz** = mandatory, 18 questions in current L01/L02, one question shown at a time, answer/explanation, retry and personalized review.

## Editorial checks for next lecture

1. Collect separately approved academic base, instructor script/slides, full transcript, assessment data for internal diagnostic use, and related prior lecture references. Confirm exact lecture number/date/group; never blend Monday and Sunday groups.
2. Map planned topics to actually delivered scenes. Note skipped, partial, carried-over concepts and uncertainty. Don't label undelivered material "delivered".
3. Create draft sequence and Learning Objectives. Connect ideas causally; do not merely transcript-dump.
4. Explain in Arabic with English technical terms intact; bilingual English version should convey the same academic idea but read naturally.
5. Identify named speakers and exact attributions **only if supported**; vague/inaccurate attribution must be anonymous or reviewed with the instructor. Never infer a learner's understanding from one public comment.
6. Base quizzes on concepts actually taught. Correct answer key and explanation must be reviewed. Each `concept` link must resolve to the correct scene (not nearest label).
7. Offer a complete end-lecture self-test with constructive retry and mapped feedback. Avoid ungrounded scores, false completeness and teaching only the test.
8. Independent Academic, Learning Design, UX and Technical QA before approval.

## Educational validity

- A checkbox that marks "read" is not proof of understanding.
- Tiny question sets per unit are learning signals, not statistically valid estimates of mastery; report sample size, including "not assessed" where appropriate.
- XP/progress is gentle motivation; do not reward wrong answers as verified mastery.
- Exam pass threshold for the current product is **80%**; practice self-assessment record is NOT an official AASTMT certificate.
- Respect privacy and permission when sharing names, photos, recordings and classroom moments.

## Four laws

Every proposed idea and design must satisfy Critical Thinking (evidence first), Systems Thinking (downstream impact), Practical Decision (minimal justified change) and Token/Resource Efficiency (focused tooling and verification). Never sacrifice accuracy to save tokens.
